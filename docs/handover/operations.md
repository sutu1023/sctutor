# 数据维护与排错

## 保存了什么

DATA_DIR默认data，包含sctutor.sqlite3、可能的WAL/SHM、原页渲染和运行记录。库里含问答、未通过草稿、题答案、掌握/复测、密钥以外的敏感学习内容。课程目录也可能含用户上传。两者不交接、不进Git、不发公共日志。

## 备份与恢复

1. 停止服务和所有CLI入库/处理；确认没有其他writer。原生Ctrl+C；容器 `docker compose down`（不加-v）。
2. 原生完整复制DATA_DIR和COURSE_DIR到私人备份目录；停止后连同现存WAL/SHM和rendered一起复制，不只拿一个活动sqlite文件。
3. Docker命名卷可用本地镜像只读打包（把VOLUME改成实际卷名，备份目录先建好）：

```bash
docker volume ls
docker run --rm --user 0 -v VOLUME:/source:ro -v "$PWD/private-backup:/backup" --entrypoint sh sctutor-handover:test -c 'tar czf /backup/volume.tgz -C /source .'
```

镜像名换成你实际构建的镜像；上例仅临时读取已有卷，不跑应用。分别备份数据卷和课件卷，文件名不要相互覆盖；private-backup不要放公开快照。容器用户无主机备份权限时选择自己的专用目录，不公开备份。
4. 恢复到**新的专用目录/卷**，不要覆盖唯一备份；按UID10001设置运行目录归属。保持相同版本先启动，检查页数/历史/小测，再升级。恢复操作必须先停writer。

Store启动会兼容迁移已有库，升级前备份；迁移失败不重置数据库。teacher/student可各有活动测验，学习数据按账号分开；不能手工删索引修故障，先复现及测试。

## 更换嵌入模型

- 不要混用不同向量空间，模型名相同也可能升级。先备份、停服务，设置新的EMBEDDING_BASE_URL/MODEL/PROVIDER及EMBEDDING_REVISION。
- 最安全：使用新的DATA_DIR（容器另建数据卷），重新入库。旧学习库保留，**不会自动迁到新库**；不要暗示可无损换库保留学习状态。
- 同维度、保留原库时可显式重新ingest。当前模型缓存键变化会重新嵌入，来源版本更新后旧知识/题目可能失效，需要重新抽取/审核。维度变化必须用新目录重建，不仅改名字；索引不是跨模型通用资产。
- 验证自己的检索问题和真实出处，再启用学习；失败不退为纯关键词、不凭模型记忆补答案。生成模型更换也需检查JSON、等级和批改语义。

## 常见问题

| 现象 | 先做什么 |
|---|---|
| 空页面/没课程 | 上传自己的PPTX，或核对COURSE_DIR；不会自动搜父目录 |
| 配置/401/额度错误 | doctor检查变量；不要贴密钥或供应商完整响应；确认权限/余额 |
| 有页面但AI不能用 | 健康检查只证明服务活着；smoke会收费，显式运行 |
| 容器连不上本机模型 | localhost是容器自身；见模型指南，不能随意放开私网HTTP |
| 原页不可用 | 默认文本模式；macOS/Office/许可/自动化权限/源版本需满足 |
| 小测没有题 | 先审核知识和题；学生不会自动补未审题 |
| 切模型后检索拒绝 | 旧向量键/维度不匹配；备份后按上节重建 |
| 断线不知是否受理 | 刷新本轮状态，不自动重发收费请求；原request_id去重 |
| 重启后似乎丢数据 | 查Compose项目名、实际卷和挂载，别删除卷或重置库 |

## 外发与风险

生成发送必要问题/证据，嵌入发送待索引文本，视觉发送单页图，Tavily发送必要搜索问题；都有隐私和费用，用户自行取得资料授权。演示账号可自行选择，设备拥有者可读库/浏览器草稿；不保证秘密隔离或考试防作弊。自动审核/同模型检查可能共同出错，教师需抽查。
